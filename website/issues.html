// Issues & contributions

GitHub Issues is the single source of truth.

All bug reports, feature requests, and known failures live in guycorbaz/kesh/issues. Each issue uses one of three templates so it lands with the right labels and triage flow.

Pick the right template

Bug report

Something is broken or behaving incorrectly. Reproduction steps, observed vs expected behaviour, and environment details.

labels: bug, triage
Open template →

Known failure (KF)

A failing test or defective behaviour outside the scope of current work. Tracked, prioritised, but not blocking the active sprint.

labels: known-failure, triage
Open template →

Feature / Change request

A new feature or a scope change to a planned story. Use this before changing scope on validated stories.

labels: enhancement, triage
Open template →

Contributing code

Pull requests are welcome. Before submitting a PR with significant scope, please open an issue first so the change can be discussed.

  • Follow the code-quality rules in CLAUDE.md (DRY, documentation, tests).
  • Add unit tests for any business logic, especially around accounting and VAT.
  • Run the full local CI checks (cargo fmt, cargo clippy, cargo test, npm run check) before pushing.
  • Write commit messages that reference the related issue (e.g. fix: round invoice totals (refs #42)).
