// About the project

An open accounting platform, built for Switzerland.

Kesh is being designed and developed in the open as a free alternative to proprietary Swiss accounting software. It targets independents, SMEs, and associations who want to keep their financial data on their own infrastructure — without sacrificing the workflows and compliance features they actually need.

Mission

Most accounting software for the Swiss market is closed-source, expensive, and cloud-only. Even the open-source options are rarely focused on Swiss specificities: the QR-Bill payment slip, the ISO 20022 banking flows mandated since 2018, the four official languages, and the locale conventions that small accountants and fiduciaries rely on every day.

Kesh exists to fill this gap. It is built around three commitments:

  • Swiss-first. QR Bill 2.2, CAMT.053, pain.001, multilingual UI, and a chart of accounts adapted to Swiss practice.
  • Self-hosted. Single-binary deployment via Docker Compose. Your accounting data never leaves your servers unless you choose to back it up off-site.
  • Free, forever. Released under the European Union Public Licence (EUPL 1.2). No tiers, no feature paywall.

Architecture

Backend — Rust workspace

A multi-crate Cargo workspace cleanly separates business logic from I/O concerns.

  • kesh-core — pure types, validation
  • kesh-db — persistence, migrations
  • kesh-api — Axum HTTP layer
  • kesh-qrbill — QR Bill 2.2
  • kesh-import — CAMT.053, CSV
  • kesh-payment — pain.001 (planned)
  • kesh-i18n — Fluent i18n

Frontend — SvelteKit 2

A modern SvelteKit SPA with Tailwind CSS 4 and TypeScript end-to-end.

  • Svelte 5 (runes mode)
  • Tailwind CSS 4
  • Vitest unit tests
  • Playwright E2E coverage
  • i18n via Fluent (FR/DE/IT/EN)

Multi-tenant by design

Every JWT carries a company_id claim. Every database query filters by that claim — defence in depth against IDOR. Companies are isolated at the row level, not just at the application layer.

Swiss compliance

QR Bill 2.2

Pixel-perfect generation per the SIX Swiss Payment Standards Implementation Guidelines.

CAMT.053.001.04

ISO 20022 bank statement import — required for automated reconciliation since 2018.

pain.001.001.03

Outgoing payment files in the format expected by Swiss banks (planned for v0.2).

Swiss VAT

Per-period VAT computation and reporting (planned for v0.2).

Locale conventions

Date format dd.mm.yyyy, thousands separator with apostrophe (1'234.50), CHF currency.

Four languages

French, German, Italian, English — the four working languages of Swiss business.

Built with BMAD

Kesh is developed using the BMAD (Breakthrough Method of Agile AI-driven Development) methodology — a structured, story-driven workflow that emphasises explicit specifications, multi-pass adversarial review, and immutable change logs. Every story flows through the same gates:

1.

Spec creation

Acceptance criteria, technical design, test plan — written before any code.

2.

Spec validation (multi-pass)

Adversarial review across multiple LLMs (Opus → Sonnet → Haiku rotation) until zero MEDIUM+ findings remain.

3.

Implementation

Test-driven development, full CI green locally before push.

4.

Code review (multi-pass)

Same adversarial loop on the implementation. Same convergence criterion.

5.

Retrospective

At the end of each epic — capture the lessons that change how the next epic is built.
