## Story

En tant qu'**Administrateur d'une installation Kesh qui va envoyer ses factures par e-mail**,
je veux **envoyer, depuis *Paramètres*, un e-mail d'essai à une adresse de mon choix, par le même transport et avec les mêmes modèles que les factures, accompagné d'une QR-facture « SPÉCIMEN »**,
afin de **savoir avant le premier envoi réel que le serveur répond, que STARTTLS passe, que l'identifiant est accepté et que l'expéditeur l'est aussi — sans rien écrire dans les livres**.

- Issue : [#1771](https://github.com/guycorbaz/kesh/issues/1771) (`enhancement`, **P2**). Demande du Project Lead du 2026-11-28 : « c'est une fonction de vérification importante ».

### Ce que lettre fait réellement d'une erreur (source lue : `lettre-0.11.23/src/transport/smtp/`)

- `Error` (`error.rs`) n'est **pas constructible** hors de lettre (`Error::new` est `pub(crate)`). Prédicats publics : `is_response`, `is_client`, `is_transient`, `is_permanent`, `is_timeout` (remonte la chaîne `source()` jusqu'à un `io::Error` `TimedOut`), `is_tls`, `is_transport_shutdown`, `status() -> Option<Code>`. **Aucun prédicat** pour les genres `Connection` et `Network`.
- ⚠️ **Un échec de poignée de main TLS n'est PAS `is_tls()`.** `async_net.rs` (rustls, `upgrade_tokio1_tls`) : `connector.connect(…).await.map_err(error::connection)?` ; tokio-rustls **0.26.6** emballe l'erreur en `io::Error::new(InvalidData, rustls::Error)` (`tokio-rustls-0.26.6/src/common/mod.rs:115`). La seule façon de reconnaître un échec TLS est de **descendre la chaîne `source()`** jusqu'à un `io::Error` dont `get_ref()` se convertit en `rustls::Error` (rustls **0.23.46**, une seule version au `Cargo.lock:3556`).
- STARTTLS absent alors que `KESH_SMTP_TLS=true` : `error::client("STARTTLS is not supported on this server")` (`async_connection.rs:235`). Aucun mécanisme d'authentification commun : `error::client("No compatible authentication mechanism was found")` (`:284`). Ce sont des **chaînes** : la story les épingle par des tests contre un faux serveur (ci-dessous), qui rougiront si lettre les change.
- Réponse négative : `code_from_response` → `Transient(code)` (4xx) ou `Permanent(code)` (5xx), le texte du serveur en `source`.
- `AsyncSmtpTransport::test_connection()` (`async_transport.rs:314`) ouvre une connexion **par le même chemin** que `send` (`AsyncSmtpClient::connection`, `:485` : connexion, EHLO, STARTTLS si requis, **AUTH** si des `Credentials` sont posés), envoie `NOOP`, puis `QUIT` (pas de `pool`). Une erreur de `test_connection` vient donc de la connexion, de TLS ou de l'authentification ; une erreur du `send` qui suit un `test_connection` réussi vient, sauf rupture réseau entre les deux, de `MAIL FROM`, `RCPT TO` ou `DATA` (`async_connection.rs:154-200`).
- Délai : `DEFAULT_TIMEOUT` = 60 s par opération réseau (`mod.rs:239`) ; le transport de Kesh ne le change pas.

- **F1 — La route.** `POST /api/v1/admin/email-test`, handler `routes::email_test::send_test_email` (module neuf `crates/kesh-api/src/routes/email_test.rs`), dans le bloc `admin_routes`, **au-dessus** de la ligne « ⚠️⚠️ TOUTE ROUTE S'AJOUTE AU-DESSUS DE CETTE LIGNE » (D1, D2). Corps : `{ "to": string, "language"?: "FR"|"DE"|"IT"|"EN" }` (`deny_unknown_fields` : un `subject` ou un `body` envoyé est un `400` — l'essai n'accepte **aucun** texte libre, ce qui le rend inutilisable comme relais). `language` absent : `company.instance_language`.
- **F2 — L'ordre des gardes.** auth → rôle Admin (`403 FORBIDDEN`) → anti-clé (`403 API_KEY_ADMIN_FORBIDDEN` ; les deux par les couches) → corps (`400 VALIDATION_ERROR`) → SMTP prêt (`412 SMTP_NOT_CONFIGURED`) → **cadence** (`429 RATE_LIMITED` + `Retry-After`) → rendu (modèle, PDF spécimen ; un échec est un `500`, l'essai n'est alors pas tenté) → transport → audit → **200**. Une adresse mal saisie ou un SMTP absent **ne consomment pas** le créneau de 30 secondes ; toute tentative qui atteint le rendu le consomme, réussie ou non.

Une seule adresse ; aucun CR/LF ne passe (refusé par les deux contrôles). Préremplissage à l'écran : `data.company.email` s'il existe, sinon vide (D3 ; l'issue proposait l'adresse de l'utilisateur, D3 la remplace).

- **F7 — Le transport : `Mailer::send_test_email`.** Une méthode neuve du trait, `fn send_test_email<'a>(&'a self, email: &'a OutgoingEmail) -> TestMailFuture<'a>`, sortie `Result<(), SmtpTestFailure>` (type neuf de `mail/`, ci-dessous). `SmtpMailer` : `transport.test_connection()` (phase **A** : connexion, TLS, authentification), puis, s'il a réussi, `build_outgoing_message` + `transport.send(…)` (phase **B** : expéditeur, destinataire, contenu) — **le même transport que les factures**, construit une fois au démarrage, sans délai ni réglage propres. Deux connexions pour un essai, assumées : c'est ce qui permet de dire à quelle étape on a échoué sans écrire un second client SMTP. `test_connection()` rendant `Ok(false)` (NOOP refusé) : échec `serverRejected`. `NoopMailer` : `Ok(())` (inaccessible derrière la garde 412). `MockMailer` : capture dans `sent_emails` comme `send_email` ; `MockMailer::failing()` rend un échec `unreachable` ; constructeur neuf `MockMailer::failing_test_with(SmtpTestFailure)` qui rend exactement l'échec donné. `send_email` et `send_password_reset` **ne changent pas** (l'envoi de factures garde son `500` opaque : hors périmètre, voir Questions).
- **F8 — La classification : ensemble clos, dans cet ordre, d'une fonction pure** `classify(phase, &lettre::transport::smtp::Error) -> SmtpTestFailure`, testée sur de **vraies** erreurs de lettre (F11) :
  1. `is_timeout()` → `timeout` ;
  2. `is_tls()`, ou un `rustls::Error` dans la chaîne `source()` (sous un `io::Error`, `get_ref()`) → `tls` ;
  3. `is_client()` en phase A dont la chaîne contient `STARTTLS` → `tls` ; dont la chaîne contient `authentication mechanism` → `authRejected` ;
  4. `status()` = `Some(code)` en phase A, code ∈ {530, 534, 535, 538} → `authRejected` ; autre code en phase A → `serverRejected` ;
  5. `status()` = `Some(code)` en phase B → `sendRejected` (« le serveur a refusé l'expéditeur, le destinataire ou le message ») ;
  6. `is_response()`, `is_client()` (autre), `is_transport_shutdown()` → `other` ;
  7. **reste** (genres `Connection` et `Network` sans prédicat, dont refus de connexion, DNS, connexion coupée) → `unreachable`.
  `SmtpTestFailure { kind, smtp_code: Option<u16>, temporary: bool (4xx), server_reply: Option<String> }`. **Site non résolu assumé** : la règle 7 est le puits — un genre d'erreur ajouté demain par lettre y tombera et s'affichera « serveur injoignable » ; écrit au doc-comment de `classify`. La distinction « expéditeur » / « destinataire » de l'issue n'est pas faite par Kesh (lettre ne dit pas quelle commande a échoué) : la réponse du serveur, rendue (F9), le dit d'ordinaire (« Sender address rejected… ») — voir Questions.
- **F9 — Aucun secret dans ce qui est rendu.** (a) **Pas de texte en phase A pour une erreur d'authentification** : `authRejected` ne rend que le code ; (b) le texte rendu des autres cas (réponse du serveur, ou message de l'erreur d'E/S ou de rustls, p. ex. « invalid peer certificate: UnknownIssuer ») passe par un assainissement **au handler**, qui dispose de la configuration : retrait de toute occurrence de `KESH_SMTP_PASSWORD`, de son encodage base64, et des encodages base64 des échanges `AUTH PLAIN` (`\0user\0pass`) et `AUTH LOGIN` (utilisateur, mot de passe) ; retrait des caractères de contrôle ; coupe à 500 caractères ; (c) `SmtpMailer` ne garde toujours pas le secret ; (d) l'audit ne garde ni texte de serveur ni secret (F10). Les journaux (`tracing`) de l'essai suivent la même règle (texte assaini).
- **F10 — L'audit.** Action neuve **`admin.email_test`**, entité `installation`, `AUDIT_ENTITY_ID_NONE`, `details = { "to", "language", "status": "delivered"|"failed", "failureKind"?, "smtpCode"? }`, écrite pour **toute tentative qui atteint le transport** (réussie ou non), après lui, en une transaction, **non bloquante** (précédent `emit_audit` de `backup_schedule.rs`, à réemployer — l'extraire dans un endroit commun plutôt que le recopier). Un `400`, `412` ou `429` n'écrit rien. Libellé neutre (le résultat est dans `details`) : `audit-log-action-admin-email-test` = « Essai d'envoi d'e-mail » et ses trois traductions. Registre : `("post", "email_test::send_test_email", Traced, SansEcritureAuJournal)`.

  `{ "status": "delivered", "to", "language", "attachmentFilename": "kesh-specimen.pdf" }` ou
  `{ "status": "failed", "to", "language", "failure": { "kind", "smtpCode": number|null, "temporary": bool, "serverReply": string|null } }`.

**Les erreurs du transport**

- **AC10 (F8).** Tests de `classify` sur des **erreurs réelles de lettre**, produites par un **faux serveur SMTP scripté** (`tokio::net::TcpListener` sur `127.0.0.1:0`, réponses écrites à la main, dans le module de tests de `mail/smtp.rs`) et un `SmtpMailer` de test au délai court (constructeur de test qui partage avec `from_config` la construction du transport — pas de second constructeur divergent) :

  - serveur qui accepte et se tait (délai 300 ms) → `timeout` ;
  - `KESH_SMTP_TLS=true` face à un serveur qui n'annonce pas `STARTTLS` → `tls` ;

  - `AUTH` refusé `535 5.7.8` → `authRejected`, `smtpCode = 535`, `temporary = false`, `serverReply = None` ;
