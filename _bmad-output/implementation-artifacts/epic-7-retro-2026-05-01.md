## 🎯 Key Learnings

### What to replicate Epic 8+

1. **Cycle adversarial review multi-LLM** (Opus → Sonnet → Haiku, contexte frais) — prouvé sur 7-3, 7-4 (régressions trouvées par Sonnet/Haiku invisibles à Opus auteur). À systématiser.
2. **Spec validate AVANT impl sur stories complexes** — Story 7-5 sauvée par 5 passes spec validate. À reproduire dès qu'une story touche > 5 modules.
3. **Helpers DRY systémiques** — `is_no_op_change` (7-3), `escape_boolean_ft` (7-4) — payback x9 et x4. Saisir les opportunités DRY pendant les passes review.
4. **Issues GitHub source de vérité 100%** — KFs spawn immediates, pas de tracking parallel local. CLAUDE.md règle respectée.

### What to change Epic 8+

1. **Spec planifiée AVANT première story** — Convention BMAD `_bmad-output/planning-artifacts/epic-X.md`. Pas d'Epic 8 ad-hoc comme Epic 7.
2. **Test locally first** — Section CLAUDE.md à créer (carry-forward Epic 6 retro non-fait).
3. **Splitter stories cross-cutting** — Règle CLAUDE.md "if > 5 modules or > 4 passes → split".
4. **Mini-rétro intermédiaire** — Si une story explose (7+ passes review), pause et check avant de continuer la suite des stories.
5. **Action items doc traités avec la même rigueur que action items code** — Pattern observé Epic 6 → Epic 7 : 100% code done, 50% doc done. Discipline à améliorer.

### Follow-through Epic 6 retro

- ✅ Renumber roadmap : 100% delivered.
- ⚠️ Epic 7 spec : créée ad-hoc (convention violée).
- ❌ "Test locally first" doc : non fait (carry-forward Epic 8).
- ❌ "Before PR" checklist : non fait (carry-forward Epic 8).

**Pattern à corriger** : action items doc plus difficiles à honorer que code. Solution Epic 8 : intégrer les doc actions dans le critical path (deadline avant Epic 8 spec).
