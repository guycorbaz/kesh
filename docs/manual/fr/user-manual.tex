\section{Bienvenue dans Kesh}

\subsection{Qu'est-ce que Kesh ?}

Kesh est un logiciel de comptabilité et de gestion conçu pour les PME, indépendants et associations en Suisse. Il vous permet de tenir votre comptabilité en partie double, d'émettre des factures avec QR Bill conformes au standard suisse, d'importer vos relevés bancaires (CAMT.053 et CSV), de réconcilier automatiquement vos paiements et de générer tous les rapports légaux nécessaires.

\subsection{Pour qui est ce manuel ?}

Ce manuel s'adresse aux utilisateurs finaux : comptables internes d'une PME, indépendants tenant leur propre comptabilité, fiduciaires gérant des dossiers clients, ou trésoriers d'association. Il ne suppose aucune connaissance technique préalable, mais une familiarité avec les concepts comptables de base (débit, crédit, plan comptable, exercice) est nécessaire.

\subsection{Conventions du manuel}

\begin{itemize}
    \item Les \emph{noms d'écrans} et \emph{libellés de boutons} apparaissent en italique.
    \item Les chemins de navigation utilisent → : \emph{Paramètres} → \emph{Utilisateurs} signifie « cliquer sur Paramètres dans le menu, puis sur Utilisateurs ».
    \item \keshkey{Ctrl+S} indique une combinaison de touches clavier.
    \item Les boîtes colorées : \emph{Note} (information), \emph{Astuce}, \emph{Attention} (avertissement).
\end{itemize}

\begin{keshnote}
Ce manuel décrit Kesh version \keshVersion. Les captures d'écran et libellés exacts peuvent varier légèrement selon la version utilisée et les traductions activées. Pour la dernière version du manuel, consultez \keshWebsite.
\end{keshnote}

\section{Premiers pas}

\subsection{Création de votre compte}

\keshscreenshot{setup-admin.png}{Écran de création du compte administrateur, au tout premier démarrage d'une installation vierge.}  % TODO capture: ecran /setup/admin (donnees factices : admin / Pierre Exemple)

L'accès à Kesh nécessite un compte utilisateur. Deux scénarios sont possibles :

\subsubsection{Création par un administrateur (cas courant)}

Si votre fiduciaire ou administrateur système a installé Kesh, il vous enverra une \textbf{invitation par email} contenant un lien de création de compte. Cliquez sur ce lien, choisissez un mot de passe fort (au moins 12 caractères, mélange de majuscules, minuscules, chiffres et caractères spéciaux), et confirmez.

\subsubsection{Onboarding initial (premier utilisateur d'une instance)}

Si vous êtes le tout premier utilisateur d'une instance Kesh fraîchement installée, vous serez accueilli par un écran d'onboarding initial vous demandant de créer le compte super-administrateur. Voir le \emph{Manuel administrateur} pour les détails.

\subsection{Connexion}

Pour vous connecter :

\begin{enumerate}
    \item Ouvrir l'URL de votre instance Kesh dans un navigateur (par exemple \keshpath{https://compta.exemple.ch}).
    \item Saisir votre email et votre mot de passe.
    \item Cliquer sur \emph{Se connecter}.
\end{enumerate}

La session reste active 15 minutes, prolongée automatiquement à chaque action grâce au système de \emph{refresh token}. Au-delà de 30 jours d'inactivité totale, vous devrez vous reconnecter.

\subsection{Récupération de mot de passe}

Si vous avez oublié votre mot de passe :

\begin{enumerate}
    \item Sur l'écran de connexion, cliquez sur \emph{Mot de passe oublié ?} (le lien n'apparaît que si votre administrateur a activé la récupération par email).
    \item Saisissez votre nom d'utilisateur \textbf{ou} votre adresse email, puis validez. Un message de confirmation générique s'affiche dans tous les cas — par sécurité, Kesh ne révèle jamais si un compte existe ou non.
    \item Ouvrez l'email reçu et cliquez sur le lien de réinitialisation. Le lien est valable \textbf{30 minutes} et ne fonctionne qu'\textbf{une seule fois}.
    \item Choisissez votre nouveau mot de passe (12 caractères minimum) et confirmez-le.
    \item Reconnectez-vous avec le nouveau mot de passe. Par sécurité, toutes vos sessions ouvertes (autres onglets, autres appareils) ont été déconnectées.
\end{enumerate}

\begin{keshwarning}
Si vous ne recevez pas l'email dans les 5 minutes, vérifiez votre dossier spam/indésirables. Si l'email n'arrive pas du tout : soit aucune adresse email n'est renseignée sur votre compte, soit l'envoi d'emails n'est pas configuré sur l'instance — dans les deux cas, contactez votre administrateur, qui peut réinitialiser votre mot de passe manuellement.
\end{keshwarning}

\begin{keshtip}
Un lien expiré ou déjà utilisé affiche « lien invalide ou expiré » : cliquez sur \emph{Refaire une demande} pour recevoir un nouveau lien. Après 5 demandes en 15 minutes, patientez 30 minutes avant de réessayer. Pour changer votre mot de passe \textbf{sans} l'avoir oublié, passez par votre compte une fois connecté (cf. section \emph{Gestion de votre compte}).
\end{keshtip}

\subsection{Déconnexion}

Cliquez sur votre avatar (coin supérieur droit) → \emph{Se déconnecter}. Tous les refresh tokens de votre session actuelle sont révoqués.

\begin{keshtip}
Si vous utilisez Kesh sur un ordinateur partagé, déconnectez-vous toujours après usage. Le mode \emph{HttpOnly Secure} des cookies de session protège contre certaines attaques, mais ne remplace pas une déconnexion explicite.
\end{keshtip}

\subsection{Vue d'ensemble de l'interface}

L'interface Kesh est organisée comme suit :

\begin{itemize}
    \item \textbf{Barre latérale gauche} : navigation principale (tableau de bord, comptabilité, factures, banque, rapports, paramètres).
    \item \textbf{Zone centrale} : contenu de la section active.
    \item \textbf{Barre supérieure} : sélecteur de company (si vous avez accès à plusieurs), notifications, avatar utilisateur, sélecteur de langue.
    \item \textbf{Pied de page} : version de Kesh, lien vers la documentation et le support.
\end{itemize}

\subsection{Choix de la langue}

Kesh est disponible en français, allemand, italien et anglais. Pour changer la langue de l'interface :

\begin{enumerate}
    \item Cliquer sur le sélecteur de langue dans la barre supérieure (drapeau ou code langue).
    \item Choisir la langue souhaitée.
    \item L'interface se recharge immédiatement dans la nouvelle langue.
\end{enumerate}

Votre choix est sauvegardé et appliqué automatiquement à votre prochaine connexion.

\section{Onboarding}

À votre première connexion sur une nouvelle company, Kesh vous guide via un assistant d'onboarding. Deux parcours sont proposés :

\keshscreenshot{onboarding-welcome.png}{Écran d'accueil de l'assistant d'onboarding : choix entre le mode exploration et le mode production.}  % TODO capture: 1er ecran onboarding

\subsection{Chemin A — Mode exploration}

Si vous souhaitez \textbf{tester Kesh sans données réelles}, choisissez le mode exploration. Kesh crée :

\begin{itemize}
    \item Une company fictive avec un plan comptable Sterchi PME.
    \item Quelques contacts d'exemple (clients, fournisseurs).
    \item Quelques produits et conditions de paiement.
    \item Un exercice fiscal en cours.
    \item Des écritures d'exemple pour illustrer les rapports.
\end{itemize}

Vous pouvez librement créer, modifier, supprimer des données dans ce mode. Pour passer en mode production, créez une nouvelle company en mode B.

\subsection{Chemin B — Mode production}

Si vous souhaitez \textbf{tenir votre comptabilité réelle}, choisissez le mode production. L'assistant vous guide à travers une série d'écrans :

\keshscreenshot{onboarding-production.png}{Saisie des coordonnées légales en mode production (raison sociale, adresse, IDE).}  % TODO capture: ecran coordonnees production (donnees factices : ABC Web Sarl, CHE-123.456.789)

\begin{enumerate}
    \item \textbf{Type d'organisation} : indépendant, association ou PME. Ce choix adapte les libellés et les valeurs par défaut (par exemple, une PME inscrite au registre du commerce renseigne obligatoirement son IDE).
    \item \textbf{Langue comptable} : langue des comptes et des rapports, indépendante de la langue de l'interface (utile si vous travaillez en français mais produisez des rapports en allemand, par exemple).
    \item \textbf{Coordonnées légales} : raison sociale (ou nom pour un indépendant), adresse, et IDE (CHE-XXX.XXX.XXX) pour une entité inscrite au registre du commerce.
    \item \textbf{Compte bancaire} : nom de la banque, IBAN et QR-IBAN éventuel (cette étape peut être passée et complétée plus tard).
\end{enumerate}

À la finalisation, Kesh met en place votre plan comptable (Sterchi PME par défaut) et votre premier exercice. Vous êtes alors prêt à saisir vos premières écritures.

\begin{keshnote}
Vous pourrez à tout moment ajouter ou modifier vos comptes bancaires après l'onboarding (\emph{Paramètres} → \emph{Comptes bancaires}) et adapter votre plan comptable (cf. section \emph{Plan comptable}).
\end{keshnote}

\begin{keshtip}
Le mode guidé pas-à-pas est recommandé pour les nouveaux utilisateurs. Les utilisateurs expérimentés peuvent passer en \emph{Mode expert} dans \emph{Paramètres} → \emph{Préférences}, ce qui réduit les confirmations et accélère la saisie.
\end{keshtip}

Le tableau de bord est votre page d'accueil après connexion. Il affiche :

\keshscreenshot{dashboard.png}{Tableau de bord : soldes bancaires, factures impayées, transactions non rapprochées et graphique du chiffre d'affaires.}  % TODO capture: dashboard avec donnees demo

\begin{itemize}

    \item Les \textbf{factures impayées} (clients + fournisseurs).
    \item Les \textbf{transactions bancaires non rapprochées} récentes.
    \item Un \textbf{graphique} chiffre d'affaires des 12 derniers mois.

Cliquer sur n'importe quel élément du tableau de bord ouvre la section correspondante en mode filtré.

\subsection{Personnalisation}

Vous pouvez réorganiser les widgets du tableau de bord par glisser-déposer. Cliquer sur l'icône \emph{⚙ Configurer} en haut à droite pour masquer ou afficher des widgets.

\section{Gestion de votre compte}

\subsection{Profil utilisateur}

Aller dans \emph{Paramètres} → \emph{Mon profil} pour modifier :

\begin{itemize}
    \item Nom et prénom.
    \item Email (génère un email de vérification au nouveau).
    \item Téléphone (optionnel).
    \item Langue et timezone par défaut.
\end{itemize}

\subsection{Changement de mot de passe}

\emph{Paramètres} → \emph{Sécurité} → \emph{Changer mon mot de passe}. Vous devez :

\begin{enumerate}
    \item Saisir votre mot de passe actuel.
    \item Saisir le nouveau mot de passe (≥ 12 caractères).
    \item Confirmer le nouveau mot de passe.
\end{enumerate}

Tous vos refresh tokens sont révoqués après changement de mot de passe : vous devrez vous reconnecter sur tous vos appareils.

\subsection{Sessions actives}

\emph{Paramètres} → \emph{Sécurité} → \emph{Sessions actives} affiche la liste des sessions ouvertes (navigateur, IP, date de connexion). Vous pouvez révoquer une session distante si vous suspectez une connexion non autorisée.

\subsection{Récupération de mot de passe oublié}

Si vous avez oublié votre mot de passe, utilisez le lien \emph{Mot de passe oublié ?} de l'écran de connexion (cf. section \emph{Premiers pas → Récupération de mot de passe}). Cette fonctionnalité nécessite qu'un serveur de messagerie (SMTP) ait été configuré par votre administrateur et qu'une adresse email soit associée à votre compte.

\subsection{Clés API (accès programmatique)}

Pour connecter Kesh à un logiciel tiers ou à une intégration (script, outil d'IA, etc.), vous pouvez créer une \textbf{clé API} (jeton d'accès personnel) depuis \emph{Paramètres} → \emph{Clés API} (\keshpath{/settings/api-keys}). Chaque clé porte un périmètre (\emph{lecture seule} ou \emph{lecture-écriture}) et une date d'expiration optionnelle ; le secret n'est affiché qu'une seule fois à la création. La gestion des clés est accessible aux rôles \emph{Comptable} et \emph{Administrateur}.

\begin{keshnote}
La documentation complète de l'API externe (authentification, points d'accès, exemples) se trouve dans \keshpath{docs/api-external.md}. Les aspects d'administration (rotation, durcissement) sont décrits dans le manuel administrateur.
\end{keshnote}

\section{Plan comptable}

Le plan comptable est la colonne vertébrale de votre comptabilité. Kesh fournit deux plans pré-configurés (Sterchi PME, KMU) et permet l'import d'un plan personnalisé.

\subsection{Visualisation}

\emph{Comptabilité} → \emph{Plan comptable}. La page affiche tous les comptes organisés selon leur structure hiérarchique :

\keshscreenshot{plan-comptable.png}{Plan comptable Sterchi PME affiché par classes hiérarchiques.}  % TODO capture: page plan comptable

\begin{itemize}
    \item Classe 1 : Actifs (1000 Caisse, 1020 CCP, 1030 Compte courant, 1100 Débiteurs, etc.).
    \item Classe 2 : Passifs (2000 Créanciers, 2200 TVA due, 2800 Capital, etc.).
    \item Classe 3 : Produits (3000 Ventes de marchandises, 3200 Ventes de services, etc.).
    \item Classe 4 : Charges de marchandises (4000 Achats de marchandises, 4200 Charges de personnel, etc.).
    \item Classe 5 : Charges de personnel (5000 Salaires, 5700 AVS/AI/APG, etc.).
    \item Classe 6 : Autres charges d'exploitation (6000 Loyer, 6500 Entretien, etc.).
    \item Classe 7 : Résultat hors exploitation et impôts.
\end{itemize}

\subsection{Ajout d'un compte}

\emph{Comptabilité} → \emph{Plan comptable} → \emph{Nouveau compte}. Saisir :

\begin{itemize}
    \item \textbf{Numéro} : par exemple 1020.1 pour un sous-compte du CCP.
    \item \textbf{Libellé} : par exemple « CCP 12-345-6 ».
    \item \textbf{Compte parent} : compte de niveau supérieur (1020 dans l'exemple).
    \item \textbf{Type} : Actif / Passif / Produit / Charge / Bilan / Résultat.
    \item \textbf{Devise} : CHF par défaut.
    \item \textbf{Compte de banque} : cocher si ce compte représente un compte bancaire (active la liaison avec l'import CAMT.053).
\end{itemize}

\subsection{Modification d'un compte}

Cliquer sur un compte ouvre son détail. Vous pouvez modifier le libellé, le compte parent, le type. Le numéro n'est pas modifiable une fois des écritures saisies (pour préserver l'audit-trail).

\subsection{Suppression d'un compte}

Un compte ne peut être supprimé que s'il n'a aucune écriture ni sous-compte. Sinon, vous pouvez l'\textbf{archiver} (le compte reste visible dans les écritures historiques mais n'est plus proposé à la saisie).

\subsection{Import d'un plan personnalisé}

\emph{Comptabilité} → \emph{Plan comptable} → \emph{Import CSV}. Format attendu :

\begin{lstlisting}
numero,libelle,parent,type,devise
1000,Caisse,,Actif,CHF
1020,Comptes courants postaux,,Actif,CHF
1020.1,"CCP 12-345-6",1020,Actif,CHF
\end{lstlisting}

\begin{keshwarning}
L'import remplace intégralement le plan comptable existant. Cette opération n'est possible qu'au début d'un exercice, avant toute saisie. Au-delà, vous devez ajouter les comptes manquants un par un.
\end{keshwarning}

\subsection{Adapter le plan à votre secteur}

Le plan Sterchi PME couvre la plupart des besoins, mais chaque PME l'adapte à son activité. Quelques exemples concrets :

\begin{itemize}
    \item \textbf{Commerce de détail} (ex. \emph{Boutique Pierre Exemple Sàrl}) : créez des sous-comptes de stock sous la classe 1 (ex. 1200.1 « Stock textile », 1200.2 « Stock accessoires ») et ventilez les ventes par rayon en sous-comptes de 3000 (ex. 3000.1 « Ventes textile », 3000.2 « Ventes accessoires ») pour suivre vos marges par catégorie.
    \item \textbf{Cabinet médical ou prestataire de services} (ex. \emph{Dr Marie Exemple}) : peu de stock, l'essentiel est dans les produits de services (3200 « Honoraires ») et les charges de personnel (classe 5). Créez un sous-compte 3200.1 par type de prestation si vous voulez analyser votre activité.
    \item \textbf{Agence web / indépendant} (ex. \emph{ABC Web Sàrl}) : facturation au forfait ou à l'heure via le catalogue produits ; suivez les sous-traitances en sous-compte de la classe 4 (ex. 4400 « Prestations de tiers »).
    \item \textbf{Artisan} (ex. \emph{Menuiserie Exemple}) : distinguez achats de matières premières (classe 4) et outillage (classe 1, immobilisations) ; un sous-compte 4000.1 « Bois » / 4000.2 « Quincaillerie » facilite le suivi des coûts de matière.
    \item \textbf{Association} (ex. \emph{Association Exemple}) : les cotisations des membres se comptabilisent en classe 3 (ex. 3600 « Cotisations »), les dons en 3601 « Dons et subventions ». Pas de TVA si l'association n'est pas assujettie.
\end{itemize}

\begin{keshtip}
Archivez (plutôt que supprimer) les comptes Sterchi PME que vous n'utilisez pas : ils disparaissent de la saisie tout en restant disponibles pour l'historique. C'est particulièrement utile pour un indépendant ou une petite structure dont le plan complet est surdimensionné.
\end{keshtip}

\section{Écritures comptables}

\subsection{Saisie d'une écriture en partie double}

\emph{Comptabilité} → \emph{Nouvelle écriture}. Renseigner :

\keshscreenshot{ecriture-saisie.png}{Formulaire de saisie d'une écriture en partie double avec ses lignes débit/crédit.}  % TODO capture: form nouvelle ecriture

\begin{itemize}
    \item \textbf{Date} : date de la transaction (entre la date de début et la date de fin de l'exercice).
    \item \textbf{Libellé} : description de l'écriture (par exemple « Vente facture F-2026-042 »).
    \item \textbf{Référence externe} : numéro de facture, référence bancaire, etc. (optionnel).
    \item \textbf{Lignes débit / crédit} : minimum 2 lignes, somme débits = somme crédits.
\end{itemize}

Pour chaque ligne :

\begin{itemize}
    \item \textbf{Compte} : sélection dans le plan comptable.
    \item \textbf{Montant} : positif uniquement (la colonne débit/crédit indique le sens).
    \item \textbf{Description ligne} : précision supplémentaire (optionnel).
\end{itemize}

\subsection{Exemple de saisie}

Vente d'une marchandise à crédit pour CHF 1'000 + TVA 8.1\% :

\begin{itemize}
    \item Débit 1100 (Débiteurs) : CHF 1'081.00
    \item Crédit 3000 (Ventes de marchandises) : CHF 1'000.00
    \item Crédit 2200 (TVA due) : CHF 81.00
\end{itemize}

Total débit = Total crédit = CHF 1'081.00. L'écriture peut être validée.

\subsection{Validation d'une écriture}

Une écriture passe par trois états :

\begin{enumerate}
    \item \textbf{Brouillon} : modification libre, n'apparaît pas dans les rapports.
    \item \textbf{Validée} : intégrée à la comptabilité, apparaît dans les rapports. Modification restreinte (cf. règles de modification ci-dessous).
    \item \textbf{Annulée} : neutralisée par une écriture de contre-passation (l'originale reste visible dans l'audit-trail).
\end{enumerate}

Pour valider : cliquer sur \emph{Valider} dans l'écriture brouillon. Une confirmation est demandée.

\subsection{Modification d'une écriture validée}

Pour des raisons d'audit-trail légal (CO Art. 957a al. 2 ch. 5 « traçabilité »), une écriture validée ne peut pas être modifiée silencieusement. Deux scénarios :

\subsubsection{Modification mineure (correction de libellé)}

Possible directement si l'utilisateur a le rôle \emph{admin} ou \emph{accountant} et si l'écriture est dans un exercice non clôturé. L'action est tracée dans l'\texttt{audit\_log} (qui a modifié, quand, ancienne valeur, nouvelle valeur).

\subsubsection{Modification d'un montant ou d'un compte}

Vous devez :

\begin{enumerate}
    \item \textbf{Contre-passer} l'écriture (création automatique d'une écriture inverse).
    \item Saisir une \textbf{nouvelle écriture} avec les montants corrects.
\end{enumerate}

Cette procédure préserve l'audit-trail légal et permet le contrôle ultérieur des modifications.

\subsection{Suppression d'une écriture}

\textbf{Une écriture validée ne peut pas être supprimée.} Vous devez la contre-passer. Une écriture en brouillon peut être supprimée librement.

\subsection{Recherche d'écritures}

\emph{Comptabilité} → \emph{Écritures}. Filtres disponibles :

\begin{itemize}
    \item Période (date début / date fin).
    \item Compte (un ou plusieurs).
    \item Montant (>=, <=).
    \item Libellé (recherche full-text).
    \item Référence externe.
    \item Statut (brouillon / validée / annulée).
\end{itemize}

\begin{keshtip}
La recherche full-text utilise l'index MariaDB FULLTEXT (Story 7-4). Pour rechercher un mot incomplet, ajoutez \texttt{*} : \texttt{Marc*} matche \texttt{Marcel}, \texttt{Marcus}, \texttt{Marchand}.
\end{keshtip}

\section{Exercices comptables}

\subsection{Concept}

Un exercice comptable est une période sur laquelle s'établissent les comptes annuels (bilan + compte de résultat). En Suisse, l'exercice est généralement civil (1\textsuperscript{er} janvier -- 31 décembre), mais d'autres périodes sont possibles (décalé, court, long).

\subsection{Création d'un nouvel exercice}

\emph{Comptabilité} → \emph{Exercices} → \emph{Nouvel exercice}. Renseigner :

\begin{itemize}
    \item \textbf{Date de début} et \textbf{Date de fin}.
    \item \textbf{Libellé} : par exemple « Exercice 2026 ».
    \item \textbf{Type} : Standard / Court / Long / Décalé.
\end{itemize}

Le nouvel exercice s'ouvre vide. Les comptes du bilan sont automatiquement reportés depuis le bilan de clôture de l'exercice précédent (si clôturé).

\subsection{Clôture d'un exercice}

\keshscreenshot{exercice-cloture.png}{Écran de clôture d'un exercice comptable.}  % TODO capture: ecran cloture exercice

\emph{Comptabilité} → \emph{Exercices} → sélectionner l'exercice → \emph{Clôturer}.

La clôture :

\begin{itemize}
    \item Verrouille toutes les écritures de l'exercice (modification impossible, contre-passation toujours possible si nécessaire).
    \item Génère les écritures de clôture (transfert des comptes de résultat vers le bilan).
    \item Reporte les soldes des comptes de bilan vers le nouvel exercice.
    \item Génère les rapports finaux (bilan de clôture, compte de résultat, balance).
\end{itemize}

\begin{keshwarning}
La clôture d'un exercice est une opération critique. Effectuez d'abord une sauvegarde complète. Une fois clôturé, l'exercice ne peut plus être modifié sans intervention administrateur exceptionnelle.
\end{keshwarning}

\subsection{Réouverture d'un exercice clôturé}

En cas d'erreur découverte après clôture, un administrateur peut rouvrir un exercice via une procédure CLI (cf. Manuel administrateur, section Dépannage). L'opération est tracée dans l'\texttt{audit\_log}. Effectuer cette opération avec parcimonie pour préserver l'intégrité légale.

\section{Facturation QR Bill}

\subsection{Création d'une facture}

\emph{Factures} → \emph{Nouvelle facture}. Renseigner :

\keshscreenshot{facture-nouvelle.png}{Création d'une facture multi-lignes avec sélection du client et du compte bancaire de réception.}  % TODO capture: form nouvelle facture

\begin{itemize}
    \item \textbf{Client} : sélection dans le carnet d'adresses (ou création à la volée).
    \item \textbf{Date de facture} : par défaut aujourd'hui.
    \item \textbf{Date d'échéance} : calculée automatiquement selon les conditions de paiement du client (modifiable).
    \item \textbf{Numéro} : généré automatiquement selon le pattern configuré (cf. \emph{Numérotation}).
    \item \textbf{Lignes de facture} : un ou plusieurs produits avec quantité, prix, TVA.
    \item \textbf{Remarques} : texte libre apparaissant en bas de facture (mention de remerciement, conditions particulières, etc.).
    \item \textbf{Compte bancaire de réception} : le compte sur lequel vous attendez le paiement (utilisé pour générer la référence QR Bill).
\end{itemize}

\subsubsection{Exemple : facture d'une agence web}

\emph{ABC Web Sàrl} facture une prestation à son client \emph{Boutique Pierre Exemple Sàrl} :

\begin{itemize}
    \item Client : Boutique Pierre Exemple Sàrl (sélectionné dans le carnet d'adresses, conditions « 30 jours net »).
    \item Ligne 1 : « Refonte site web » — 1 × CHF 4'500.00.
    \item Ligne 2 : « Maintenance mensuelle » — 3 × CHF 150.00 = CHF 450.00.
    \item Total : CHF 4'950.00. Échéance calculée à 30 jours.
    \item Compte de réception : le compte bancaire QR-IBAN de l'agence.
\end{itemize}

À la validation, Kesh attribue le numéro \texttt{F-2026-0042}, génère le PDF QR Bill, et crée l'écriture comptable automatique (Débit 1100 Débiteurs / Crédit 3200 Honoraires). Si les lignes de la facture portent un taux de TVA, Kesh comptabilise aussi automatiquement la TVA due au compte de TVA (p.~ex. 2200) ; ici l'agence n'est pas assujettie, l'écriture se limite donc à CHF 4'950.00 (cf. \emph{Décompte TVA}).

\subsection{Validation d'une facture}

Une facture passe par trois états :

\begin{enumerate}
    \item \textbf{Brouillon} : modification libre, pas de numéro définitif, n'apparaît pas dans les rapports.
    \item \textbf{Validée} : numéro définitif attribué, PDF QR Bill généré, écriture comptable créée automatiquement (Débit 1100 Débiteurs / Crédit 3000 Ventes + 2200 TVA).
    \item \textbf{Payée} : marquée comme payée après réconciliation avec une transaction bancaire entrante.
\end{enumerate}

\subsection{Numérotation des factures}

Le numéro de facture est généré automatiquement selon un pattern configurable dans \emph{Paramètres} → \emph{Facturation} :

\begin{itemize}
    \item Pattern par défaut : \texttt{F-AAAA-NNNN} (ex. F-2026-0042).
    \item Patterns alternatifs : \texttt{INV-AAAAMM-NNN}, \texttt{F\{company\_id\}-AAAA-NNNN}, etc.
    \item La numérotation est strictement séquentielle dans un exercice (CO Art. 957a al. 2 ch. 5 « traçabilité »).
    \item L'attribution du numéro se fait dans une transaction DB \texttt{SERIALIZABLE} pour garantir l'unicité même en cas de validations concurrentes.
\end{itemize}

\subsection{Génération du PDF avec QR Bill}

\keshscreenshot{facture-qrbill.png}{Exemple de PDF de facture avec section de paiement QR Bill 2.2 détachable en bas de page.}  % TODO capture: PDF facture QR Bill (donnees factices)

À la validation, Kesh génère un PDF conforme au standard \href{https://www.six-group.com/en/products-services/banking-services/standardization/qr-bill.html}{QR Bill 2.2} (norme suisse 2020+) :

\begin{itemize}
    \item Format A4, page principale + section de paiement séparable en bas.
    \item QR code suisse contenant toutes les informations de paiement (créancier, débiteur, montant, IBAN, référence structurée, communication).
    \item Section de paiement en français (modifiable selon la langue du client).
    \item Compatible scan par les e-banking suisses et applications mobiles (Raiffeisen, PostFinance, UBS, Credit Suisse, Migros Bank, etc.).
\end{itemize}

Le PDF est téléchargeable depuis la facture validée. Vous pouvez ensuite l'envoyer manuellement par email (depuis votre messagerie habituelle) ou l'imprimer pour un envoi postal. Kesh ne dispose pas d'envoi de facture intégré : le service de messagerie interne (SMTP) n'est utilisé que pour la récupération de mot de passe.

\begin{keshtip}
La référence structurée du QR Bill est calculée selon la norme ISO 11649 (RF Reference) ou le format suisse QRR (Référence Kesh). Le choix du format dépend du compte bancaire de réception : les comptes IBAN suisses standard utilisent IS0 11649, les comptes QR-IBAN utilisent QRR.
\end{keshtip}

\subsection{Échéancier des factures}

\emph{Factures} → \emph{Échéancier}. Vue d'ensemble des factures :

\keshscreenshot{facture-echeancier.png}{Échéancier des factures : à échoir, échues impayées, et payées.}  % TODO capture: page echeancier

\begin{itemize}
    \item Factures à échoir (dans les 30 prochains jours).
    \item Factures échues impayées (en retard).
    \item Factures payées (historique).
\end{itemize}

Cliquer sur une facture en retard permet de générer un rappel (template configurable).

\subsection{Avoirs et notes de crédit}

Un avoir (note de crédit) annule une facture validée : c'est le moyen \textbf{correct} d'annuler une facture déjà comptabilisée (on ne supprime jamais une écriture passée, principe d'intangibilité comptable). Pour créer un avoir, ouvrez la facture validée concernée et cliquez sur \textbf{« Créer un avoir »} (réservé aux rôles \emph{Comptable} et \emph{Administrateur}). En une seule étape, Kesh :

\begin{itemize}
    \item crée un avoir reprenant toutes les lignes de la facture, avec son propre numéro issu d'une séquence dédiée (par défaut \keshcommand{AV-2026-0001}, configurable dans \emph{Paramètres → Facturation}) ;
    \item génère automatiquement l'\textbf{écriture de contre-passation} : l'inverse exact de l'écriture de la facture (la créance client, le produit et la TVA due — une ligne par taux — sont contre-passés), de sorte que le \textbf{solde du client revient à zéro} ;
    \item bascule la facture d'origine au statut \textbf{« annulée »} (sa propre écriture reste intacte).
\end{itemize}

L'avoir est consultable dans \emph{Avoirs} (menu \emph{Quotidien}), avec un \textbf{PDF « Avoir »} téléchargeable (mention « Avoir », référence à la facture d'origine, sans section QR de paiement). Le \emph{Décompte TVA} de la période tient compte de l'annulation (la TVA de la facture annulée est exclue).

\begin{keshnote}
En version actuelle, l'avoir est \textbf{total} (il annule la facture entière). L'avoir \emph{partiel} et le remboursement d'une facture \emph{déjà encaissée} (un avoir est refusé sur une facture marquée payée) sont prévus pour une version ultérieure, de même que les fichiers de paiement pain.001 (paiements sortants, Epic 12).
\end{keshnote}

\section{Import bancaire}

L'import bancaire est l'étape clé pour automatiser votre comptabilité. Kesh supporte deux formats :

\subsection{Import CAMT.053 (ISO 20022)}

\keshscreenshot{import-camt.png}{Prévisualisation d'un import de relevé bancaire CAMT.053 avant validation.}  % TODO capture: ecran import CAMT preview

Le format CAMT.053 est le standard suisse officiel pour les extraits de compte bancaire. Il est fourni par toutes les banques suisses en complément ou remplacement du format CSV propriétaire.

\subsubsection{Récupération du fichier CAMT.053}

\begin{itemize}
    \item \textbf{e-banking} : section « Téléchargement » ou « Extraits » → format CAMT.053 / ISO 20022 XML.
    \item \textbf{Multibanking} : si vous utilisez un agrégateur comme Multibanking ou Klippa, exportez en CAMT.053.
    \item \textbf{PostFinance Yellownet} : Menu Documents → Type de document : CAMT.053.
\end{itemize}

\subsubsection{Import dans Kesh}

\begin{enumerate}
    \item \emph{Banque} → \emph{Imports} → \emph{Nouvel import}.
    \item Sélectionner le compte bancaire cible (préalablement créé dans le plan comptable, marqué « Compte de banque »).
    \item Glisser-déposer le fichier XML CAMT.053 ou cliquer sur \emph{Parcourir}.
    \item Cliquer sur \emph{Importer}.
\end{enumerate}

Kesh parse le fichier, extrait les transactions, détecte les doublons (si le fichier contient des transactions déjà importées) et affiche un rapport :

\begin{itemize}
    \item Nombre de transactions importées.
    \item Nombre de doublons détectés (ignorés).
    \item Nombre de transactions rejetées (anomalies de format, montants invalides, etc.).
\end{itemize}

\subsection{Import CSV multi-encodage}

\keshscreenshot{import-csv.png}{Configuration d'un profil d'import CSV (mapping des colonnes, encodage, séparateur).}  % TODO capture: ecran profil CSV

\subsubsection{Profils banque}

Le format CSV n'étant pas standardisé, chaque banque propose son propre format de colonnes, séparateurs et encodage. Kesh permet de créer des \emph{profils banque} réutilisables :

\begin{enumerate}
    \item \emph{Banque} → \emph{Profils CSV} → \emph{Nouveau profil}.
    \item Saisir le nom du profil (ex. « UBS CHF Compte courant »).
    \item Uploader un fichier CSV exemple.
    \item Mapper les colonnes : date, libellé, montant, référence, devise, etc.
    \item Configurer l'encodage : UTF-8, ISO-8859-1, Windows-1252, etc.
    \item Configurer le séparateur : virgule, point-virgule, tabulation.
    \item Sauvegarder.
\end{enumerate}

\subsubsection{Import avec un profil existant}

\begin{enumerate}
    \item \emph{Banque} → \emph{Imports} → \emph{Nouvel import CSV}.
    \item Sélectionner le profil banque adéquat.
    \item Sélectionner le compte bancaire cible.
    \item Uploader le fichier CSV.
    \item Cliquer sur \emph{Importer}.
\end{enumerate}

\subsection{Détection des doublons}

\keshscreenshot{import-doublons.png}{Avertissement de détection de doublons lors d'un ré-import de fichier bancaire.}  % TODO capture: ecran doublons

Kesh détecte automatiquement les transactions déjà importées en utilisant une empreinte unique calculée à partir de :

\begin{itemize}
    \item La date.
    \item Le montant.
    \item La référence bancaire (si fournie).
    \item Le libellé.
    \item Le compte bancaire cible.
\end{itemize}

Les doublons sont ignorés silencieusement (cf. Story Epic 8 « Détection doublons + rejet partiel »). Le rapport d'import indique le nombre de doublons trouvés.

\subsection{Rejet partiel}

Si un fichier contient un mélange de transactions valides et invalides, Kesh importe les valides et reporte les invalides dans un rapport. Vous pouvez corriger le fichier source et le réimporter (les valides déjà importées sont ignorées via détection de doublons).

\begin{keshtip}
Importez vos relevés bancaires \textbf{au moins une fois par semaine} pour faciliter la réconciliation. Plus le délai entre la transaction et l'import est court, plus il est facile de se souvenir du contexte et donc de rapprocher rapidement.
\end{keshtip}

\section{Réconciliation bancaire}

La réconciliation consiste à rapprocher les transactions bancaires importées avec les écritures comptables ou les factures de votre comptabilité.

\subsection{Réconciliation automatique}

\keshscreenshot{reconciliation-auto.png}{Propositions de réconciliation automatique entre transactions bancaires et factures.}  % TODO capture: ecran reconciliation auto (propositions)

\subsubsection{Algorithme de matching}

Lors de l'import, Kesh propose automatiquement des correspondances entre transactions bancaires et factures impayées / écritures comptables. L'algorithme utilise un score combinant :

\begin{itemize}
    \item \textbf{Montant} : correspondance exacte = score maximal, écart < 1 CHF = score moyen.
    \item \textbf{Date} : transaction bancaire dans les 30 jours de l'échéance facture = bon score.
    \item \textbf{Référence} : matching exact de la référence QR Bill = score très élevé.
    \item \textbf{Libellé} : matching partiel du nom du client = score moyen.
\end{itemize}

Le score total détermine la confiance du match. Au-dessus d'un seuil paramétrable (par défaut 80\%), le match est proposé pour acceptation. Au-dessus de 95\%, le match peut être pré-validé automatiquement (option \emph{auto-accept high confidence}).

\subsubsection{Acceptation des propositions}

\emph{Banque} → \emph{Réconciliation}. La page affiche :

\begin{itemize}
    \item Les transactions bancaires non rapprochées (avec proposition s'il y en a).
    \item Les factures impayées candidates.
\end{itemize}

Pour chaque transaction :

\begin{itemize}
    \item \emph{Accepter} : valide le rapprochement. L'écriture comptable est créée automatiquement (Débit 1020 Banque / Crédit 1100 Débiteurs).
    \item \emph{Rejeter} : la proposition est ignorée. La transaction reste à rapprocher manuellement.
    \item \emph{Modifier} : sélectionner une autre facture ou écriture.
\end{itemize}

\subsubsection{Acceptation par lot}

Si plusieurs propositions sont à valider d'un coup, cocher les transactions concernées et cliquer sur \emph{Accepter sélectionnées}. L'opération est atomique : soit toutes les transactions sont rapprochées avec succès, soit aucune. Les transactions ayant échoué (par exemple racing condition avec un autre utilisateur ayant déjà rapproché la facture) sont reportées dans une liste \emph{failed[]} avec un code d'erreur précis (cf. \emph{Pattern batch FailedProposal} dans la doc CLAUDE.md projet).

\subsection{Réconciliation manuelle}

\keshscreenshot{reconciliation-manuelle.png}{Rapprochement manuel : sélection explicite de la facture correspondant à une transaction.}  % TODO capture: ecran reconciliation manuelle

Si aucune proposition automatique n'est pertinente :

\begin{enumerate}
    \item Cliquer sur \emph{Rapprocher manuellement} sur une transaction non rapprochée.
    \item Sélectionner une facture impayée OU une écriture comptable existante OU créer une nouvelle écriture à la volée.
    \item Valider.
\end{enumerate}

\subsection{Éclatement d'une transaction (split)}

\keshscreenshot{reconciliation-split.png}{Éclatement d'une transaction bancaire en plusieurs écritures (paiement partiel, ventilation).}  % TODO capture: ecran split

Cas d'usage : votre banque crédite votre compte d'un virement groupé de CHF 5'000 correspondant en réalité à 3 factures (CHF 2'000 + CHF 1'500 + CHF 1'500).

\begin{enumerate}
    \item Cliquer sur la transaction → \emph{Éclater}.
    \item Saisir les montants des sous-éléments (somme = montant initial).
    \item Pour chaque sous-élément, choisir la facture ou l'écriture correspondante.
    \item Valider.
\end{enumerate}

L'écriture comptable globale est éclatée en N écritures (1 par sous-élément).

\subsection{Règles d'affectation automatique}

\keshscreenshot{reconciliation-regles.png}{Définition d'une règle d'affectation automatique des transactions récurrentes.}  % TODO capture: ecran regles d'affectation

\emph{Banque} → \emph{Règles}. Définir des règles pour automatiser la création d'écritures pour les transactions récurrentes.

Exemple : tous les ordres permanents loyer (CHF 2'500 chaque 1\textsuperscript{er} du mois vers le bailleur) → règle qui crée automatiquement l'écriture Débit 6000 Loyer / Crédit 1020 CCP.

\subsubsection{Création d'une règle}

\begin{enumerate}
    \item \emph{Banque} → \emph{Règles} → \emph{Nouvelle règle}.
    \item Saisir le \textbf{nom} de la règle (ex. « Loyer mensuel »).
    \item Définir les \textbf{conditions} : libellé contient « LOYER » OU montant entre 2'400 et 2'600 OU compte tiers IBAN = CH00 ...
    \item Définir l'\textbf{action} : créer écriture Débit compte X / Crédit compte Y avec libellé Z.
    \item Définir la \textbf{priorité} : règles évaluées dans l'ordre des priorités.
    \item Sauvegarder.
\end{enumerate}

\subsubsection{Application des règles}

Lors de l'import bancaire, Kesh applique automatiquement les règles aux transactions importées. Les écritures sont créées en mode brouillon par défaut (validation manuelle) ou en mode validé direct (option \emph{auto-validate rules}).

\subsubsection{Acceptation par lot d'écritures issues de règles}

Si plusieurs écritures sont en brouillon issues des règles d'affectation, cocher et valider en lot. Même pattern \emph{FailedProposal per-proposal} qu'en réconciliation : retour HTTP 200 avec \texttt{\{ accepted, failed \}}.

\section{Rapports comptables}

\subsection{Bilan}

\keshscreenshot{rapport-bilan.png}{Bilan : actifs, passifs et capitaux propres à une date donnée.}  % TODO capture: rapport bilan

\emph{Rapports} → \emph{Bilan}. Affiche les actifs et passifs au format légal Art. 959 et 959a CO :

\begin{itemize}
    \item Actif circulant : trésorerie, créances, stocks.
    \item Actif immobilisé : immobilisations corporelles, incorporelles, financières.
    \item Capitaux étrangers court terme.
    \item Capitaux étrangers long terme.
    \item Capitaux propres : capital, réserves, bénéfice / perte de l'exercice.
\end{itemize}

Filtres : date de référence (par défaut fin d'exercice en cours), exercice à comparer (N-1).

\subsection{Compte de résultat}

\keshscreenshot{rapport-resultat.png}{Compte de résultat : produits, charges et résultat de la période.}  % TODO capture: rapport compte de resultat

\emph{Rapports} → \emph{Compte de résultat}. Disponible en deux présentations (Art. 959b CO) :

\begin{itemize}
    \item Par nature : produits nets, charges de matériel, charges de personnel, autres charges, amortissements, résultat exceptionnel.
    \item Par fonction : produits nets, coût d'acquisition, charges d'administration, charges de distribution.
\end{itemize}

Le choix est défini par défaut au niveau de la company, modifiable par rapport.

\subsection{Balance des comptes}

\emph{Rapports} → \emph{Balance}. Liste tous les comptes avec leurs soldes débiteurs et créditeurs. Filtres : période, niveau de détail (comptes principaux uniquement, ou tous sous-comptes).

\subsection{Journal des écritures}

\emph{Rapports} → \emph{Journal}. Liste chronologique de toutes les écritures de la période sélectionnée. Vue brute, idéale pour audit ou contrôle.

\subsection{Décompte TVA}

\emph{Rapports} → \emph{TVA}. Produit le décompte de la TVA pour la période sélectionnée, à partir des écritures réellement comptabilisées.

\begin{itemize}
    \item \textbf{TVA due} : la TVA facturée sur les ventes, ventilée par taux (8.1\%, 3.7\%, 2.5\%, 0\%). Elle est comptabilisée automatiquement lors de la validation de chaque facture de vente (compte \emph{TVA due}, p.~ex. 2200).
    \item \textbf{TVA récupérable} (impôt préalable) : la TVA payée sur les achats, lue du solde du compte d'impôt préalable (p.~ex. 1171). Elle s'alimente via l'assistant de saisie d'achat (cf. \emph{Saisie d'une écriture}), qui pré-remplit la ligne d'impôt préalable à partir d'un taux.
    \item \textbf{Solde net dû à l'AFC} : TVA due − TVA récupérable. Un solde négatif signifie un crédit d'impôt en votre faveur.
\end{itemize}

\paragraph{Réconciliation et alerte d'écart.} Kesh recoupe le montant de TVA due calculé depuis les factures avec le solde réellement comptabilisé au grand livre. Si une écriture validée a été modifiée à la main et ne correspond plus à la TVA facturée, un \textbf{bandeau d'alerte} affiche l'écart constaté. L'alerte est informative (elle ne bloque pas le rapport) et vous invite à vérifier les écritures validées modifiées manuellement, afin que « les montants du décompte correspondent aux écritures comptables ». Le décompte et l'écart figurent aussi dans les exports PDF et CSV.

\begin{quote}
\small \emph{Limitation actuelle (v0.3)} : le format de décompte officiel AFC (e-décompte ESTV) et la méthode des taux de la dette fiscale nette (TDFN) ne sont pas encore couverts. Le décompte de Kesh fournit les montants (due, récupérable, solde net) à reporter manuellement sur le formulaire AFC.
\end{quote}

\subsection{Visualisation et exports}

Tous les rapports peuvent être :

\begin{itemize}
    \item \textbf{Visualisés en HTML} dans l'interface (interactif, tri, filtre).
    \item \textbf{Exportés en PDF} (format paginé, conforme structure Art. 959/959a/959b).
    \item \textbf{Exportés en CSV} (analyse Excel ou import dans un autre outil).
\end{itemize}

\section{Exports de souveraineté}

\subsection{Concept}

L'\emph{export ZIP de souveraineté} (Story 9-2b) est l'export global de toutes vos données comptables dans un format ouvert et lisible 10 ans (conformité OLICo Art. 9 al. 1.b). Il garantit que vous n'êtes \textbf{jamais prisonnier de Kesh} : à tout moment, vous pouvez extraire l'ensemble de vos données pour migration vers un autre logiciel ou archivage légal.

\subsection{Contenu du ZIP}

\begin{itemize}
    \item \texttt{metadata.json} : métadonnées de l'export (version Kesh, date, user, hash SHA-256 par fichier).
    \item \texttt{accounts.csv} : plan comptable.
    \item \texttt{contacts.csv} : carnet d'adresses.
    \item \texttt{products.csv} : catalogue produits.
    \item \texttt{journal\_entries.csv} : toutes les écritures.
    \item \texttt{invoices.csv} : toutes les factures.
    \item \texttt{bank\_transactions.csv} : toutes les transactions bancaires.
    \item \texttt{fiscal\_years.csv} : tous les exercices.
    \item \texttt{reports/} : tous les rapports PDF générés (bilan, P\&L, balance, journal).
\end{itemize}

\subsection{Génération}

\keshscreenshot{export-souverainete.png}{Génération d'un export de souveraineté (archive ZIP annuelle pour la conservation OLICo).}  % TODO capture: ecran export souverainete

\emph{Exports} → \emph{Export global ZIP}. Sélectionner :

\begin{itemize}
    \item Exercice(s) à inclure (par défaut tous).
    \item Format des rapports inclus : PDF, CSV, ou les deux.
\end{itemize}

Cliquer sur \emph{Générer}. Le ZIP est téléchargeable immédiatement (durée de génération : 5--30 secondes selon le volume).

\subsection{Vérification d'intégrité}

Le \texttt{metadata.json} contient un hash SHA-256 par fichier du ZIP. Pour vérifier l'intégrité après archivage :

\begin{lstlisting}[language=bash]
# Extraction du ZIP
unzip kesh-export-2026-05-20.zip -d kesh-export/
cd kesh-export/

# Verification du hash de chaque fichier
for f in *.csv reports/*.pdf; do
    actual=$(sha256sum "$f" | cut -d' ' -f1)
    expected=$(jq -r ".sha256_per_file[\"$f\"]" metadata.json)
    if [ "$actual" = "$expected" ]; then
        echo "✓ $f OK"
    else
        echo "✗ $f CORROMPU"
    fi
done
\end{lstlisting}

\subsection{Conservation OLICo 10 ans}

Pour la conservation légale 10 ans (CO Art. 958f al. 1) :

\begin{enumerate}
    \item Générer l'export ZIP à la clôture de chaque exercice.
    \item Calculer le SHA-256 du ZIP complet : \keshcommand{sha256sum kesh-export-2026.zip > kesh-export-2026.zip.sha256}.
    \item Stocker le ZIP + le fichier hash sur un support adapté (cloud avec immutabilité, NAS avec snapshot, DVD-R, etc.).
    \item Re-vérifier le hash périodiquement (recommandation : annuel) pour détecter toute corruption.
    \item Conserver le manuel utilisateur correspondant à la version Kesh utilisée (procédure documentée OLICo Art. 9 al. 1.b ch. 4).
\end{enumerate}

\section{Multi-tenant pour fiduciaires}

\subsection{Sélecteur de company}

Si vous êtes membre de plusieurs companies (cas fiduciaire), la barre supérieure affiche un \textbf{sélecteur de company}. Toutes les vues (écritures, factures, rapports) sont automatiquement filtrées par la company active.

\subsection{Bascule entre companies}

Cliquer sur le sélecteur → choisir la company cible. L'interface se recharge avec les données de la nouvelle company sélectionnée. Un audit-trail est généré (qui a basculé vers quelle company à quel moment).

\subsection{Isolation des données}

Vos rôles et permissions sont définis par company. Vous pouvez être \emph{admin} de la company A et seulement \emph{viewer} de la company B. L'isolation est stricte au niveau de chaque requête API (cf. Story Epic 7-1 « multi-tenant scoping refactor »).

\subsection{Audit cross-company}

Un super-administrateur peut consulter l'\texttt{audit\_log} agrégé de plusieurs companies (mode \emph{tenant overview}). Les utilisateurs standards voient uniquement l'\texttt{audit\_log} de leur company active.

\section{Notifications et audit}

\subsection{Centre de notifications}

L'icône cloche dans la barre supérieure affiche les notifications récentes :

\begin{itemize}
    \item Factures à échoir dans les 7 jours.
    \item Factures en retard de paiement.
    \item Transactions bancaires non rapprochées depuis > 7 jours.
    \item Écritures en brouillon non validées depuis > 7 jours.
    \item Anomalies détectées (doublons, déséquilibres, etc.).
\end{itemize}

\subsection{Audit-trail}

\emph{Paramètres} → \emph{Audit-trail}. Liste chronologique de toutes les actions effectuées sur votre company :

\begin{itemize}
    \item Connexions et déconnexions.
    \item Création / modification / suppression d'entités (contacts, produits, factures, écritures).
    \item Imports bancaires.
    \item Réconciliations.
    \item Exports.
    \item Modifications de paramètres.
\end{itemize}

Filtres : période, utilisateur, type d'action, entité concernée.

\begin{keshnote}
L'audit-trail est \textbf{insert-only} : aucune action ne peut être modifiée ou supprimée. Il garantit la traçabilité conforme à OLICo Art. 9 al. 1.b ch. 4.
\end{keshnote}

\section{FAQ et dépannage utilisateur}

\subsection{Mes écritures ne se balancent pas, que faire ?}

Vérifiez que la somme des débits égale exactement la somme des crédits (à 1 centime près). Kesh refuse de valider une écriture déséquilibrée. Si vous avez un écart d'arrondi sur de la TVA, utilisez un compte d'écart d'arrondi (typiquement 6997 ou 7997).

\subsection{Mon QR Bill ne s'affiche pas correctement, que faire ?}

\begin{itemize}
    \item Vérifiez que votre compte bancaire est configuré avec un IBAN suisse valide.
    \item Si vous utilisez un QR-IBAN, assurez-vous qu'il est marqué comme tel dans \emph{Paramètres} → \emph{Comptes bancaires}.
    \item Testez le PDF généré avec une application e-banking suisse (PostFinance, Twint Pro, Raiffeisen) : le QR code doit être scanné en moins d'une seconde.
\end{itemize}

\subsection{Mon import CAMT.053 reporte 0 transactions, que faire ?}

\begin{itemize}
    \item Vérifiez que le fichier est bien au format CAMT.053 (extension \texttt{.xml} et balises ISO 20022 dedans).
    \item Vérifiez que le compte bancaire cible est correctement sélectionné.
    \item Vérifiez la date des transactions : si elles sont toutes antérieures à la date de début de votre exercice, elles sont ignorées.
    \item Consultez les logs d'import (lien \emph{Voir détails} sur l'import) pour identifier d'éventuelles erreurs de parsing.
\end{itemize}

\subsection{Une transaction bancaire ne propose aucun match automatique, est-ce normal ?}

Oui, si :

\begin{itemize}
    \item Le montant ne correspond à aucune facture impayée à 1 CHF près.
    \item La référence ne correspond à aucune référence QR Bill structurée.
    \item Le libellé est trop vague (« Virement », « Versement », sans détail).
\end{itemize}

Procédez à un rapprochement manuel, ou créez une règle d'affectation pour les transactions récurrentes.

\subsection{Comment changer la langue d'une facture ?}

La langue de la facture suit la langue de communication du client (champ \emph{Langue} du contact). Pour une facture ponctuelle dans une autre langue, vous pouvez forcer la langue dans le formulaire de création de facture.

\subsection{Comment exporter mes données pour migration ?}

Utilisez l'\emph{Export ZIP de souveraineté} (cf. section dédiée). Le format CSV ouvert est importable dans n'importe quel autre logiciel comptable supportant les standards Swiss PME.

\subsection{Comment puis-je revenir en arrière sur une action ?}

Selon l'action :

\begin{itemize}
    \item Écriture brouillon : suppression libre.
    \item Écriture validée : contre-passation (création d'une écriture inverse).
    \item Facture validée : passage en avoir + génération d'une nouvelle facture.
    \item Rapprochement bancaire : déliaison (\emph{Délier} sur la transaction).
\end{itemize}

L'\texttt{audit\_log} garde toujours la trace de l'action originale ET de l'action de retour.

\section{Conseils d'utilisation au quotidien}

\subsection{Routine recommandée}

\paragraph{Quotidienne (5--10 min)}
\begin{itemize}
    \item Vérifier les notifications.
    \item Saisir les écritures du jour (s'il y en a).
\end{itemize}

\paragraph{Hebdomadaire (30--60 min)}
\begin{itemize}
    \item Importer les relevés bancaires de la semaine.
    \item Réconcilier les nouveaux mouvements (acceptation des propositions auto + manuelle pour le reste).
    \item Valider les écritures en brouillon.
    \item Émettre les factures de la semaine.
\end{itemize}

\paragraph{Mensuelle (2--4 h)}
\begin{itemize}
    \item Pointage du bilan et du compte de résultat.
    \item Génération des rapports d'analyse.
    \item Suivi des impayés (rappels de factures en retard).
\end{itemize}

\paragraph{Annuelle (1--2 jours)}
\begin{itemize}
    \item Clôture de l'exercice (génération bilan, P\&L, balance définitifs).
    \item Génération de l'export ZIP de souveraineté.
    \item Archivage légal 10 ans.
    \item Création du nouvel exercice.
    \item Test de restauration de sauvegarde (avec l'administrateur).
\end{itemize}

\subsection{Bonnes pratiques}

\begin{itemize}
    \item Saisissez les écritures \textbf{le plus tôt possible}, idéalement le jour même de la transaction.
    \item Utilisez des libellés \textbf{descriptifs et standardisés} : facilite la recherche et la lecture des rapports.
    \item Liez systématiquement les transactions bancaires aux factures via la référence QR Bill structurée.
    \item Vérifiez votre balance mensuellement : tout écart suspect doit être investigué immédiatement.
    \item Gardez votre plan comptable \textbf{simple et stable}. Évitez de créer des sous-comptes inutiles : ils alourdissent l'analyse.
\end{itemize}

\section{Annexes}

\subsection{Glossaire comptable}

\begin{description}
    \item[Actif] Ce que possède l'entreprise (liquidités, créances, stocks, immobilisations). Classe 1 du plan comptable.
    \item[Amortissement] Constatation comptable de la perte de valeur d'une immobilisation sur sa durée d'utilisation.
    \item[Audit-trail (piste d'audit)] Journal infalsifiable de toutes les modifications comptables (qui, quand, quelle valeur), exigé par le CO Art. 957a.
    \item[Avoir (note de crédit)] Document qui annule tout ou partie d'une facture émise (l'inverse d'une facture).
    \item[Balance des comptes] Liste de tous les comptes avec leurs soldes débiteurs et créditeurs à une date donnée.
    \item[Bilan] État du patrimoine d'une entreprise à une date donnée (actifs = passifs + capitaux propres).
    \item[Capitaux propres] Fonds appartenant aux propriétaires (capital, réserves, résultat reporté). Différence entre actifs et dettes.
    \item[Charge] Coût supporté par l'entreprise (achats, salaires, loyer). Classes 4 à 6.
    \item[Compte de résultat] État des produits et charges d'une période (bénéfice ou perte).
    \item[Créance] Somme due à l'entreprise par un tiers (typiquement un client). Compte « Débiteurs » (1100).
    \item[Débit / Crédit] Sens d'une opération comptable. Par convention, débit = entrée pour l'actif et sortie pour le passif.
    \item[Dette] Somme due à un tiers (fournisseur). Compte « Créanciers » (2000).
    \item[Échéance] Date à laquelle une facture devient exigible.
    \item[Écriture en partie double] Saisie respectant le principe somme(débits) = somme(crédits) (cf. \emph{Partie double}).
    \item[Exercice] Période sur laquelle s'établissent les comptes annuels.
    \item[Grand-livre] Ensemble des comptes individuels reprenant toutes les écritures qui les concernent.
    \item[IDE] Identifiant Unique des Entreprises (Suisse), format CHE-XXX.XXX.XXX.
    \item[Journal] Enregistrement chronologique de toutes les écritures comptables.
    \item[Lettrage] Rapprochement d'une facture avec son paiement pour solder la créance ou la dette correspondante.
    \item[Liquidités] Avoirs immédiatement disponibles (caisse, comptes bancaires et postaux).
    \item[Partie double] Principe selon lequel toute opération est enregistrée sur au moins deux comptes, débit = crédit.
    \item[Passif] Origine des ressources de l'entreprise (dettes + capitaux propres). Classe 2.
    \item[Plan comptable] Liste structurée et hiérarchisée des comptes utilisés.
    \item[Produit] Revenu généré par l'activité (ventes, honoraires, cotisations). Classe 3.
    \item[Provision] Charge estimée et comptabilisée d'avance pour un risque ou une dépense future probable.
    \item[QR Bill] Standard suisse 2020+ de facture avec QR code (SIX Group).
    \item[QR-IBAN] IBAN spécial pour les paiements QR Bill avec référence structurée.
    \item[Réconciliation bancaire] Rapprochement des transactions du relevé bancaire avec les écritures comptables (factures, paiements).
    \item[Référence structurée] Référence numérique unique attachée à un paiement (ISO 11649 ou QRR).
    \item[Report à nouveau] Solde d'un compte de bilan reporté d'un exercice sur le suivant à la clôture.
    \item[Sous-compte (auxiliaire)] Compte de détail rattaché à un compte principal (ex. 1100.1 pour un client important).
    \item[TVA] Taxe sur la valeur ajoutée (Loi LTVA, RS 641.20).
\end{description}

\subsection{Nouveautés et limites (v0.3.0)}

Nouveautés de la version 0.3.0 :

\begin{itemize}
    \item TVA suisse comptabilisée : TVA due aux ventes (comptabilisée automatiquement à la validation des factures), impôt préalable sur les achats via l'assistant de saisie, décompte TVA (solde net dû à l'AFC) et réconciliation du rapport avec le grand livre (cf. \emph{Décompte TVA}). Le décompte officiel AFC / e-décompte ESTV reste à venir.
\end{itemize}

Disponibles depuis la version 0.2.0 :

\begin{itemize}
    \item Récupération de mot de passe oublié par email en libre-service (cf. \emph{Premiers pas}).
    \item Export et import complets d'une installation depuis l'interface d'administration (format \keshcommand{.keshbackup} ; cf. manuel administrateur).
    \item Clés API (jetons d'accès personnels) pour les intégrations tierces (cf. \emph{Gestion de votre compte → Clés API}).
\end{itemize}

Fonctionnalités non encore disponibles :

\begin{itemize}
    \item Mono-devise CHF (multi-devises prévu pour une version ultérieure).
    \item Décompte TVA au format officiel AFC / e-décompte ESTV (les montants du décompte Kesh sont à reporter manuellement sur le formulaire AFC).
    \item Pas d'assistant d'avoirs / notes de crédit dédié — utiliser la contre-passation manuelle (prévu Epic 12).
    \item Pas de fichiers de paiement pain.001 (prévus Epic 12).
    \item Pas d'envoi de facture par email intégré (téléchargement PDF + envoi manuel).
    \item Pas de signature électronique qualifiée (QES) sur les exports (verdict (b) de la recherche réglementaire, prévu Epic 14).
    \item Format PDF standard, non PDF/A (migration prévue selon ISO 19005).
\end{itemize}
